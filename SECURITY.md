## Security Architecture

### Commercial Tracking Model

This tool operates on a **free tier with commercial tracking**. Understanding this is critical for security reviewers:

**What we collect:**
- API keys (UUID, tied to email if provided)
- Scan metadata (tool count, risk count, timestamps)
- Lead information (email, company, role, IP)
- Rate limit counters (IP + endpoint, hourly window)

**What we don't collect:**
- Your MCP server source code
- Tool implementation details beyond name + description
- Scan payloads are not stored server-side after report generation

**Data retention:**
- API keys: Until revoked by user
- Scan records: 90 days
- Lead data: 24 months (for enterprise follow-up)
- Rate limit counters: 1 hour rolling window

### IDOR Protection

All report endpoints (`/scans`, `/report/:id`) are scoped to the requesting API key. Users can only access their own scan history and reports.

### Report ID Entropy

Report IDs use full UUIDv4 (`scan_` + 32 hex chars = 128-bit entropy). They are not sequential, timestamp-based, or enumerable.

### Rate Limiting

| Endpoint | Limit | Window |
|----------|-------|--------|
| `/create-key` | 10 per IP | 1 hour |
| `/register` | 5 per IP | 1 hour |
| `/scan` | 5 per API key | 1 month (free tier) |

### CCS Signatures

Scan reports include a `ccs_receipt.signature` field. This is a SHA-256 hash of `report_id:api_key:timestamp`. It is **not** a cryptographic attestation of scan accuracy — it is a **commercial integrity marker** that ties the report to the scanning session.

For production security verification, upgrade to Pro which includes manual review and compliance reports (SOC2, ISO42001).

### Open Source Considerations

This project is licensed under **Apache-2.0**. The commercial tracking endpoints (`/create-key`, `/register`, `/scans`) are part of the **hosted free tier**, not the self-hosted version.

**If you fork and self-host:**
- You are responsible for your own data handling compliance
- The tracking code is provided for transparency, not obligation
- We recommend clearly documenting your data practices if you modify them

**If you use our hosted free tier:**
- Your data is handled per this policy
- Tracking is the trade-off for free scans
- Upgrade to Pro ($49/mo) removes ads/upgrade prompts

## Known Limitations

1. **Static keyword matching** — The 5 risk rules use pattern matching against tool names and descriptions. False positives are expected (calibration included in reports).

2. **No runtime analysis** — We analyze tool metadata, not execution behavior. A tool named `get_weather` could theoretically do anything at runtime.

3. **No supply chain verification** — We don't verify the MCP server's dependencies, build process, or deployment environment.

4. **CCS is a commercial marker, not a security guarantee** — The signature proves the report was generated by our system, not that the scan is 100% accurate.

## Security Best Practices for Users

1. **Don't share your API key** — It's tied to your usage and leads
2. **Review scan results manually** — Automated scanning is a starting point, not a conclusion
3. **Upgrade to Pro for compliance** — Free tier is for development/exploration
4. **Self-host if you need full control** — Apache-2.0 allows it
